## 1. 核心的動作原理 (Single Source of Truth)

- **SSoT の遵守**: 実装・設計の判断は、常に `docs/REQUIREMENTS.md`（要件）と `docs/DESIGN.md`（デザイン）を絶対的な正解として扱うこと。
- **セットアップ・構造**: 環境構築やディレクトリ構成については `README.md` を参照すること。
- **優先順位**: 1. ユーザーの最新の指示, 2. 本ルールファイル, 3. `docs/` 配下のドキュメント。

## 2. 開発・運用ルール

- **使用言語**: 報告、計画、コミットメッセージ等はすべて**日本語**で生成すること。
- **GitHub 運用**:
  - **Issue ベース**: 原則 Issue に基づいて作業するが、タイポ修正や軽微な UI 調整等の小規模な修正は Issue 不要。
  - **ブランチ戦略**: Issue 番号を含むブランチ名（例: `feat/issue-1-xxx`）を基本とする。Issue なしの場合は `fix/minor-update` 等を使用。
- **Git 運用**: 意味のある単位で `git push` し、コミットメッセージは内容が伝わる日本語で記述すること。
- **透明性の確保**: 重要な技術選定や設計変更を行う際は、必ず `notify_user` でユーザーの承認を得ること。
