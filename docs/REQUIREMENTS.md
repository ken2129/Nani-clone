# 要件定義書

## 1. 概要

Gemini API を利用したリアルタイム翻訳ツールです。
学習および公開練習を目的としたプロジェクトであり、ユーザー自身が発行した API キーを利用する**BYOK (Bring Your Own Key)** 構成を採用します。

---

## 2. コア機能 (MVP)

- **リアルタイム翻訳**: 原文の入力停止から **500ms** 経過後に自動で翻訳処理を実行します。
- **BYOK 対応**: ユーザーが独自の Gemini API キーを入力・削除できる機能を備えます。
- **キーの保持方式**: セキュリティと利便性を両立するため、API キーは **httpOnly Cookie** に保存されます。
  - **セキュリティ**: JavaScript からアクセスできないため、XSS 攻撃によるキー盗取を防止します。
  - **利便性**: 一度登録すればブラウザを閉じても再入力の必要はありません。
- **言語操作機能**:
  - 日本語 ⇄ 英語の切り替え機能（将来的に他言語への拡張を想定）。
  - 翻訳元と翻訳先の言語を入れ替えるスワップ機能。
- **ユーティリティ**:
  - 翻訳結果のワンクリックコピー機能。
  - 入力文字数のリアルタイムカウント表示（上限: 5,000 文字）。

## 3. エラーハンドリング

- **API キーエラー**: 無効なキーの場合、エラーメッセージを表示し再入力を促す。
- **ネットワークエラー**: 接続失敗時にリトライ可能なエラーメッセージを表示。
- **レート制限**: API 制限に達した場合、待機時間を案内するメッセージを表示。
- **入力制限超過**: 文字数上限を超えた場合、入力を制限しユーザーに通知。

---

## 4. セキュリティ方針

- **API キーの保護**: API キーはブラウザの `httpOnly Cookie` にのみ保持され、サーバー側のデータベース等には永続保存しません。
- **プロキシ中継**: 翻訳リクエスト時に Cookie から API キーを読み取り、バックエンド経由で Google Gemini API を呼び出します。フロントエンドの JavaScript にキーが露出することはありません。

---

## 5. 開発ステップ

1. **UI 構築**: 入出力エリアおよび設定用フォームの作成（Vanilla CSS によるモダンなデザイン）。
2. **ストレージ実装**: API キーをバックエンド経由で `httpOnly Cookie` に保存・削除するロジックの構築。
3. **プロキシ実装**: Cookie からキーを読み出し、Gemini API を呼び出すバックエンド API の作成。
4. **翻訳ロジック**: `useEffect` とタイマーを用いたデバウンス処理の実装。
5. **公開**: Vercel へのデプロイと環境設定。
